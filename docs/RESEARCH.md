# Research and runtime testing

Benwa can use `SEARCH_PROVIDER=langsearch` with the server-only `LANGSEARCH_API_KEY`. It searches the general web and returns five bounded source excerpts per request. Query text and returned text consume LangSearch's free token allowance; the provider's actual account limits remain authoritative. A conservative local daily ceiling defaults to 100,000 tokens. Reservations, settled tokens, request timestamps and cooldowns persist in PostgreSQL's `ResearchUsage` table. Unknown/failed usage remains reserved, and 429 retry instructions are respected. New keys do not clear this local account-wide allowance. Results remain untrusted discovery leads, not verified demand or project-stage completion.

Ordinary source reading retains the existing public HTTPS/DNS/robots checks. If extraction fails or a page contains too little text, `FIRECRAWL_API_KEY` enables a bounded markdown fallback. Explicit robots denial, authentication denial, private destinations and throttling are not bypassed. Firecrawl's credit endpoint must report the documented free 1,000-credit plan before a scrape/browser operation; paid plans are blocked. Provider-reported remaining credits and a separate local cap of 900 reserved credits per billing period both apply. No billing, paid upgrade or automatic top-up is enabled. Only basic markdown scraping is requested, without AI extraction, PDF parsing or enhanced proxy extras.

`FIRECRAWL_BROWSER_TESTS_ALLOWED=false` is the default. Turning it on requires the operator's consent to send generated project HTML to Firecrawl. It never uploads `.env`, the database, dashboard or arbitrary host files. The existing `browser.test` tool can then use a short isolated Firecrawl session when local Docker is absent. Each session has a 60-second TTL, a 20-second execution timeout, a conservative four-credit reservation and cleanup in `finally`. The test runner is fixed application code, not generated shell/Node execution on this PC. Page network requests are blocked, and the generated HTML is loaded directly into the isolated browser; no public tunnel is created.

Interactive HTML needs declarative `checks` alongside `path`: `fill` with `selector`/`value`, `click` with `selector`, and `text` with `selector`/`contains`. At least one text assertion is required. Script errors, missing expected results, provider execution errors and malformed evidence fail the test. Screenshots and static inspection alone cannot pass an interactive project's TESTING gate. Successful test evidence remains separate from customer-demand validation and publication consent.

On 13 November, LangSearch returned real maker-pricing sources and Firecrawl returned IANA's public Example Domains documentation. The operator explicitly approved sending generated HTML to Firecrawl for isolated browser testing. The running PC configuration now enables this feature. Three live margin assertions passed for Maker Margin (50%, 25%, and -25%), with a returned screenshot hashed locally. The browser-report.json file in the project records the exact tested artifact hash. The project remains in TESTING because its original break-even scope is not yet complete; demand and revenue remain unvalidated. No public tunnel or dashboard upload was used.
